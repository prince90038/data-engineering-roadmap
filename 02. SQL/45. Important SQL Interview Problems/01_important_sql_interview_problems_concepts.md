# Important SQL Interview Problems

## 1. Why these questions matter

Interview problems test your ability to reason about SQL logic, data relationships, and business constraints.

They often focus on:

- joins
- grouping
- ranking
- filtering
- windows functions
- edge cases like nulls and duplicates

---

## 2. Common beginner problems

Examples include:

- second highest salary
- employees earning more than the department average
- duplicate records
- customers without orders
- employees without departments

These questions help build core SQL fluency.

---

## 3. Intermediate problems

Typical intermediate problems include:

- top 3 salaries per department
- consecutive login days
- customers with consecutive purchases
- duplicate transactions
- missing dates
- employees who changed departments
- latest record per customer

These require deeper use of grouping, filtering, and window functions.

---

## 4. Advanced problems

Common advanced SQL interview questions include:

- running totals
- moving averages
- month-over-month growth
- year-over-year growth
- gaps and islands
- sessionization
- customer retention
- cohort analysis
- SCD Type 2 logic
- incremental load logic
- deduplication with window functions

---

## 5. Approach to interview problems

A strong strategy is to:

- understand the business requirement
- identify the table relationships
- decide whether window functions are needed
- think about edge cases like nulls and duplicates
- validate the result with sample data

---

## 6. Key learning goals

By the end of this topic, you should be able to:

- identify common SQL interview problem categories
- reason through simple and intermediate business logic in SQL
- explain when ranking and window functions are appropriate
- solve practical SQL challenges with confidence

---

## 7. Practice prompts

Try solving:

- second highest salary
- customers without orders
- employees with the highest salaries in each department
- moving averages for daily sales
- deduplicate records while preserving the latest version

Interview SQL is about clear logic and careful reasoning, not memorization alone.
